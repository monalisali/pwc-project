2. Glossary

For the full glossary of Titan terms the central glossary is maintained here.

Term

Definition

VAT Invoice

This is a China specific term. A Value-Added Tax (VAT) invoice is a document issued by an accountable entity. A VAT invoice sets out the details of a taxable supply and all related information as prescribed by VAT law. In the context of this document ,this is to mention the Golden tax VAT invoice verified with China Golden tax system.

Special VAT Invoice

This is a China specific term. Special VAT Invoices are issued by Trafigura to its counterparty when selling commodities or providing taxable services. The Special VAT invoices are used for VAT deduction purposes. Trafigura also receives Special VAT invoice from counterparty for purchase trades.

General VAT Invoice

This is a China specific term. General VAT invoices cannot be used for VAT deduction purposes. General  VAT Invoices are issued by Trafigura to its counterparty when selling commodities or providing tax services. Trafigura also receives General VAT invoice for counterparty for purchase trades.

VAT Invoice Number

This is a China specific term. The golden tax invoice number approved/ generated by Golden Tax system.

Commercial Invoice

A seller-issued invoice that provides detailed information about goods or services sold to a buyer and is used for customs declaration, tax assessment, and international trade settlement. It serves as a commercial and shipping document supporting domestic and cross-border trade transactions. It is also called international invoice in Titan.

FR-07

General VAT invoice

General VAT invoice with tax amount should be interfaced to Titan PI in the API as below, due to General VAT tax is irrecoverable and Oracle does not support 'IRR' tax code.

  • If the input VAT is not deductible (i.e. 6% Service General VAT), the tax status should be interfaced to Titan PI as ‘Outside scope’ & tax code ‘CN099PI’.
  • If the tax is exempted (e.g. Gold), the tax status should be interfaced to Titan PI as ‘Applicable’ & tax code ‘CN205PI’.

Tax amount to be consolidated into net amount and pass to Titan net amount,

Tax amount pass to Titan as 0.

Notes:

General VAT whose VAT is irrecoverable, there will be a break between TMP and Oracle in tax amount reconciliation, but total invoice amount reconciliation is balanced.

Service General VAT with 6% tax rate: Tax Status-Outside Scope, Tax Code: CN099PI

8. Non-functional Requirement

NFR is to capture all the non-functional processes and system related requirements for effective deployment and maintenance of the interfaces.

#

Type

Description

NFR-01

Performance

VAT invoice Volumes check Section 5 on page Integration Options between China TMP and Titan Purchase Invoice & Sales Invoice - CC&E - Confluence.

China International PI volume: monthly average 270 cargo & service PI&CN.

The interface should support processing at least 500 VAT invoices per batch without performance degradation. The batch execution should be completed within 1 hour under normal operating conditions.

NFR-02

Error Handling and Retry

The interface should provide automatic failure recovery mechanisms. Failed interface transactions should be retried automatically every hour.

Users should be able to identify failed invoices and trigger resubmission where applicable.

NFR-03

Data Integrity

The interface should ensure data accuracy and completeness throughout the transmission process. No invoice records should be lost during transmission.

NFR-04

Reliability

The interface should support once-and-only-once processing. Each invoice should be processed only once for a given interface transaction without duplication.

Reprocessing of failed invoices should not result in duplicate invoices.

NFR-05

Availability

The interface should support normal business operations in China. Planned maintenance windows should be communicated in advance. Temporary unavailability should not result in invoice data loss.

NFR-06

Audit Trail

For each interface transaction, the following information should be logged:

  • Invoice Number
  • Invoice Type
  • Interface Execution Time
  • Sending System
  • Receiving System
  • Interface Status
  • Error Message (if applicable)
  • User who confirmed the invoice for booking

NFR-07

Monitoring and Alerting

The interface should be actively monitored.

  • Failed interface executions should generate alerts to the support team in near real-time
  • Alerts should be raised to the support team if no invoices are successfully transmitted during a scheduled batch run.
  • Alerts should be raised to the support team if invoices status is 'Sent' without final status of 'Approved' ,'Failed' or 'Cancelled' after 5 mins.
  • Interface health status should be available for support teams.

NFR-08

Security

The interface should comply with enterprise security standards.

  • All API communications should use encrypted transport protocols.
  • Only authorized systems should be allowed to invoke the APIs.
  • Authentication credentials should be securely managed and not stored in plain text.
  • Financial and tax-related data should be protected during transmission and storage.

NFR-09

Scalability

The solution should support future business growth.

  • The interface should support increasing invoice volumes without major redesign.
  • Additional business line and future China legal entities should be supported through configuration where feasible.

What is the schedule of Oracle Acct. period switch? Considering below scenario:

1-Sep: TMP open new period of Sep, a new invoice with issuance date of 1-Sep received in TMP and user complete attribution on 1-Sep.

If Oracle side new period is not opened yet, Titan PI will receive failure from Oracle.

If above scenario will happen, need to decide the API start timing for each month.

Oracle new period is always open at the 1st day of a new month, so the scenario in this question will never happen.

Release Plan

  • The full integration scope is documented on the page, and will be delivered in phases based on available team capacity.
  • Only the Service PI integration from TMP to Titan PI is planned for delivery in 27.R1.
  • All remaining integration scope is targeted for delivery in 27.R2.

API Design

  • Aligned on a REST-based API architecture with real-time individual requests, validation checks, and processing responses.
  • For China international invoices where the golden source remains in Titan PI and invoice data needs to be synchronized to TMP: TMP will invoke the Titan PI API at scheduled intervals to get delta invoice data instead of synchronous API calls.
  • Cargo invoices, non-pooled service invoices, and pooled service invoices will be implemented as three separate APIs. TMP will invoke the relevant API based on the invoice type.

  • For data elements that TMP already synchronizes from SRD, the corresponding GUIDs should be passed instead of names, including: GC, CP, Tax Code
  • Cost Code will be passed as the Cost Code Name (e.g., C32P, C31).

  • Titan PI does not maintain Accounting Period information and therefore cannot return this field in its API response.
